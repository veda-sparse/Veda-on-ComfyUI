# FA4 私有副本（vendoring）

## 目标

依赖固定版本、打过补丁的 FlashAttention-4，同时不影响同一个 ComfyUI 进程里的其他节点，并且在
Windows 上能 import。

## 设计与不变量

- **为什么不原地 patch**：Miowtion 在进程里替换 `sys.modules["flash_attn.cute.*"]`，要求在任何人
  import FA4 之前执行。ComfyUI 一个进程加载几十个节点，加载顺序不可控，原地替换还会影响所有用
  FA4 的节点；而且锁定 `flash-attn-4==4.0.0b32` 会和别的节点的版本要求互相覆盖。
- **做法**：`tools/vendor_fa4.py` 从锁定 sha256 的 PyPI wheel 生成三个私有包：
  - `fa4_upstream`：原样（给 sm90 / sm100）；
  - `fa4_sm8x`：应用 `tools/fa4_patches/sm8x` 的 7 个补丁（SM80 块稀疏前向 / 反向主循环、
    DenseBlockMaskTorch、低开销 launch、解除 arch-12 限制），打完后每个文件的 sha256 必须等于
    Miowtion 锁定的结果。
  - `quack`：FA4 的运行时辅助库 QuACK（`quack-kernels` 0.6.5，Apache-2.0），两份 FA4 共用；
    它和 FA4 有同样的 Windows 问题，所以也必须私有化（`testing/` 子包不带）。
  - 三个包都把 `flash_attn.cute` / `quack` 的 import 改成相对 import（含子包的相对层级、
    FA4 指向私有 quack 的 `..quack`、`import x.y` 这类副作用 import），并应用
    `COMPAT_EDITS`。
- **Windows 兼容**：FA4（b32 与最新的 b33）在 `cache_utils.py` 顶层 `import fcntl`，QuACK
  在 `cache/jit.py`、`cache/async_compile.py` 顶层 `import fcntl`，FA4 的 `interface.py`
  会把它们都 import 进来，所以原版在 Windows 上根本 import 不了——尽管 CuTe DSL 从 4.8.0
  起已经有 Windows wheel。补丁：`fcntl` 改为可选，没有时文件锁直接放行（只影响 JIT 缓存的
  跨进程加锁）。另外 QuACK 的 forkserver 预加载写死了模块名 `quack.cache._pool_preload`，
  改成按自己的 `__name__` 推出私有路径。不用"往 `sys.modules` 塞一个假 `fcntl`"的办法：
  那会让别的包误以为自己在 Unix 上。
- 生成的文件头部都有 "Generated by tools/vendor_fa4.py"；`VENDORED.json` 记录版本、wheel、
  补丁列表和兼容修改。CI 的 `--check` 保证仓库里的副本与生成结果逐字节一致。

## 升级流程

1. 改 `FA4_VERSION` / `FA4_WHEEL` / `FA4_WHEEL_SHA256`，必要时重做补丁（`git am` 到新的上游
   commit，导出新的 patch 文件），更新 `UPSTREAM_SHA256` / `PATCHED_SHA256`。
2. `python tools/vendor_fa4.py` 重新生成；`COMPAT_EDITS` 不匹配时工具会直接失败。
3. 同步更新 `requirements-fa4.txt` 里的运行时依赖版本（升级 QuACK 同理：改
   `QUACK_*` 锁定值；FA4 要求的 QuACK 版本见其 wheel 的 `Requires-Dist`）。
4. 在 SM8x、SM90、SM100、SM12x（以及 Windows）上跑 `tests/gpu`，结果写进 hardware.md。
   单独一个 `kernels:` 提交。

## 踩坑记录

- **import 改写吞掉换行**：`import flash_attn.cute.x as y` 的规则用 `\s*$` 匹配到了行尾换行，
  替换后两行粘在一起成了语法错误。对策：保留捕获的结尾空白；`tests/unit` 里对所有生成文件做
  `ast.parse` 和相对 import 目标存在性检查。

- **QuACK 的 Windows 问题是在 Windows 真机上才发现的**：FA4 修好 `fcntl` 后，import 链
  又在 QuACK 里撞上同一个问题。对策：QuACK 一并 vendor；`tests/unit` 检查所有 vendored
  包都没有顶层 `import fcntl`。
